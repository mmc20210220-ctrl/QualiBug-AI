## 去重修复第二轮：UUID归一化 + [DB]标签清理 + 小数值支持（完成）

### 问题

1. 标准 UUID 格式 `4321e175-6ad3-4303-9cee-b8b9acd61ca9` 不匹配归一化规则（规则4要求大写字母 `[A-Z]{2,}`）

### 修复
1. **`_extract_business_key_for_dedupe`** — 增加 UUID 归一化（标准 RFC 4122 格式 `[0-9a-fA-F]{8}-...`）和 `[DB]` 标签清理
2. **`_translate_title`** — DB 正则 `(-?\d+)` 改为 `(-?\d+\.?\d*)` 支持小数值

### 归一化规则完整清单（通用，不硬编码业务概念）
1. 单引号值 `'RF001'` → `'<ID>'`
2. 双引号值 `"RF001"` → `"<ID>"`
3. 标准 UUID `4321e175-...` → `<ID>`
4. 6位以上纯数字 → `<ID>`
5. 字母前缀+连字符 `ORD-001` → `<ID>`
6. =号后的值 `=100`/`=-6999.00` → `=<V>`

## uuid类型检测根治（完成）

### 问题
之前只靠参数名含"uuid"或真实ID匹配uuid格式检测，但参数名 `order_id` 不含"uuid"，`_fetch_real_id` 返回 `QUALIBUG_UNRESOLVED_ID` 时无法判断，仍生成 `"0"/"-1"/"99999999"` 触发 PostgreSQL uuid 类型错误。

### 修复
1. **`route_catalog_builder.py`** — `RouteEntry` 新增 `path_param_formats: dict[str, str]`，OpenAPI 解析时提取参数的 `schema.format`（uuid/int64/string 等），`to_route_map` 输出 `path_param_formats`
2. **`discovery_engine._generate_test_values`** — 从 `resolved.get("path_param_formats")` 获取参数格式，`format == "uuid"` 时用 nil uuid 边界值
3. **`discovery_engine._execute_verification`** — fallback 时从 `resolved.get("path_param_formats")` 检测 uuid 类型

### uuid检测三级fallback
1. OpenAPI schema format == "uuid"（最准确）
2. 参数名含 "uuid"
3. 真实ID匹配 RFC 4122 格式
