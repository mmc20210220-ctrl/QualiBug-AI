# QualiBug Shop PRD

## 1. 背景

QualiBug Shop 是一个面向综合电商的中台+前台系统，支持商品浏览、搜索、加购、优惠、下单、支付、售后、物流和后台管理。目标是给测试引擎提供接近企业真实资料的测试环境：资料完整但存在版本演进、历史兼容、需求冲突、边界遗漏和旧系统包袱。

## 2. 角色

| 角色 | 能力 |
|---|---|
| 游客 | 浏览商品、搜索、查看详情、加入购物车 |
| 注册用户 | 登录、下单、支付、退款、查看订单 |
| 会员用户 | 享受会员价、优惠券、积分 |
| 管理员 | 管理商品、订单、库存、售后、审计日志 |
| 客服 | 处理退款、修改地址、备注订单 |

## 3. 核心流程

### 3.1 商品搜索

用户可按关键词、分类、价格区间、评分、上架状态筛选商品。搜索应仅返回已上架商品，排序支持价格升序、价格降序、评分优先、销量优先。

### 3.2 购物车

用户可以添加商品到购物车，购物车商品数量应为 1 到 99。库存不足时不能继续加购。不同 SKU 应独立计算数量。游客购物车应在登录后自动合并到用户购物车。

### 3.3 优惠

系统支持金额券、折扣券、免邮券、会员价、满减活动。默认优惠优先级为：会员价 > 满减 > 优惠券 > 免邮。不同活动是否可叠加由活动配置控制。

### 3.4 下单

用户提交订单时必须校验库存、商品状态、地址、优惠有效期、支付金额。订单创建后状态为 CREATED，支付成功后状态为 PAID，发货后状态为 SHIPPED，确认收货后状态为 FINISHED。

### 3.5 支付

支付渠道包括余额、银行卡、微信、支付宝。支付金额必须与订单应付金额一致。支付回调需要幂等处理，同一订单不能重复支付成功。

### 3.6 售后

未发货订单可全额退款，已发货订单需要走退货流程。退款金额不能超过订单实付金额。优惠券退款规则按活动配置处理。

### 3.7 管理后台

管理员可以上下架商品、修改库存、处理退款、查看审计日志。客服只能处理售后，不能修改商品价格和库存。

## 4. 非功能要求

- 首屏加载时间 P95 小于 2 秒。
- 商品搜索 P95 小于 300ms。
- 支付回调必须幂等。
- 订单创建需要防止并发超卖。
- 移动端 360px 到 430px 宽度必须可用。
- 图片必须有可理解的替代文本。
- 后台操作必须记录审计日志。
- 所有金额计算统一使用分为单位。

## 5. 验收方式

测试引擎需要结合 PRD、接口文档、数据库设计、UI/UX 设计图、历史问题记录、代码和运行行为判断系统是否满足业务、接口、UI、性能、稳定性、兼容性和安全要求。
