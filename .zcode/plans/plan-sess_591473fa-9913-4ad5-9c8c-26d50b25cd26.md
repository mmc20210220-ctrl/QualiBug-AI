# Round 1: Benchmark Bug Factory + Metrics

## 问题
当前 enterprise_bug_factory/ benchmark_runtime/ benchmark_evaluator/ 各自独立，缺少统一端到端 Benchmark Bug Factory。没有基准线，系统永远"自我感觉优化"。

## 新建文件

### 1. ai_test_asset_center/benchmark_bug_factory.py — 统一 Bug 工厂
- BugTemplate: 行业无关模板(risk_type, severity, oracle_rules, trigger_pattern, variant_dimensions)
- BugFactory: 接受行业规格生成 bug 实例(含 oracle/expected/actual/evidence_required)
- GroundTruthStore: 写入 PRIVATE_BLOCKLIST 保护位置
- PublicArtifactGenerator: 从模板生成 OpenAPI/PRD
- RuntimeSeeder: 注入 benchmark_runtime 目标
- 支持7个行业: CRM, Ecommerce, ERP, Finance, Medical, Education, SaaS

### 2. ai_test_asset_center/benchmark_baseline_tracker.py — 基准线追踪
- 每次 run 保存 metrics 快照
- 对比上次计算 delta
- 检测 regression 告警
- 纯 JSON 输出

### 3. tests/test_benchmark_bug_factory.py — 测试
- 验证每个行业的 bug 生成
- 验证隐私保护
- 验证 metrics 计算

## 修改文件

### 4. benchmark_evaluator/metrics.py — 增强指标
- 新增 F1 Score
- 新增 per-risk-type recall breakdown
- 新增 per-severity recall breakdown
- 新增 evidence_strength_weighted_recall
- 新增 false_positive_analysis

### 5. ai_test_asset_center/benchmark_compute.py — 端到端集成
- 打通 BugFactory -> RuntimeTarget -> DiscoveryEngine -> Evaluator
- 新增 run_benchmark_end_to_end()

### 6. tools/generate_benchmark_dashboard.py — 移除假数据
- 修复硬编码的 "detected" 状态(第151-172行)

## Round 2-5 概要
- R2: capability_gap_resolver.py — plan_only 转可执行任务
- R3: learning_generator.py — 从 confirmed bug 生成新 Probe/Oracle/Fixture
- R4: oracle_dsl/ — WHEN-THEN DSL 转强断言
- R5: Dashboard — 展示前4轮真数据

## 设计原则
1. 盲测纪律: Ground truth 在 PRIVATE_BLOCKLIST 下
2. 行业无关: 不硬编码
3. 不造假: metrics 从真实数据计算
4. 可观测: 每阶段 JSON 日志
