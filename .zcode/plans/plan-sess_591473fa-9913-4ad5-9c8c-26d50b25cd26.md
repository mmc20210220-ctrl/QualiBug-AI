# Round 3: Learning → New Probe/Oracle/Fixture Generation

## 问题诊断
当前学习管线只做两件事：**提取模式存起来**（bug_pattern_memory, closed_loop_feedback）、**给已有探针加权重排序**（risk_clue_pool）。没有任何组件从 confirmed bug 生成真正新的探针、Oracle 或 Fixture。`closed_loop_feedback.py` 的 mutation hints 生成了但从未被消费。

## 新建文件

### 1. `ai_test_asset_center/learning_generator.py` — 核心学习生成器
- **`LearningGenerator`** 类，接受 confirmed findings + 项目上下文（entities, roles, endpoints）
- **`ProbeGenerator`**:
  - `generate_variant_probes(confirmed_bug, context)` → 从 confirmed bug 的角色变体、实体变体、端点变体、参数变体生成新探针
  - `generate_cross_entity_probes(pattern, entities)` → 同一 risk_type 在不同实体上生成探针（如: 在 /orders 发现 IDOR → 在 /products, /users 也生成 IDOR 探针）
- **`OracleGenerator`**:
  - `generate_sibling_oracles(confirmed_bug, all_endpoints)` → 同一 oracle 类型扩展到兄弟端点（如: GET /orders/{id} 发现 state_flow bug → 对 GET /products/{id} 也加 state_flow oracle）
  - `generate_derived_oracles(pattern, oracle_family)` → 从 confirmed bug 推导同类 oracle
- **`FixtureGenerator`**:
  - `generate_reproduction_fixture(confirmed_bug)` → 生成最小可复现数据
  - `generate_regression_fixture(confirmed_bug)` → 生成回归测试数据
- **`LearningManifest`**: 追踪每次生成了什么、来源哪个 confirmed bug、什么理由

### 2. `tests/test_learning_generator.py` — 测试
- 验证从 confirmed bug 能生成变体探针
- 验证跨实体 oracle 生成
- 验证 fixture 生成
- 验证学习 manifest 完整性

## 修改文件

### 3. `ai_test_asset_center/closed_loop_feedback.py`
- 集成 LearningGenerator: mutation hints 不再只是文本，而是实际调用 ProbeGenerator 生成具体探针
- 在 `build_closed_loop_context()` 返回中加入 `generated_probes` 列表
- 将生成的探针注入到下次扫描的 probe 池

### 4. `ai_test_asset_center/confirmed_bug_flywheel.py`
- 在 `build_confirmed_bug_flywheel()` 中调用 LearningGenerator
- 每次有新的 confirmed bug 时自动生成 variant probes / sibling oracles
- 将生成结果记录到 flywheel profile 的 `generated_artifacts` 字段

## 设计原则
1. **从真实 confirmed bug 生成**: 不凭空造探针，每个新探针都有来源 confirmed bug 和变异理由
2. **可追踪**: LearningManifest 记录 source_bug_id → generated_artifact 的完整链路
3. **不重复**: 生成前检查是否已存在相同探针（dedup by method+path+actor+risk_type）
4. **行业无关**: 变体逻辑基于通用模式（角色变体、实体变体、参数边界），不硬编码行业
5. **安全边界**: 生成的探针继承 source bug 的 execution_policy，不自动提升为可执行
