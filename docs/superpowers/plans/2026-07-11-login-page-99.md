# QualiBug Login Page 99-Point Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved Trusted Technology authentication experience across login, registration, and password reset with verified service health, accessible password controls, and responsive enterprise-grade presentation.

**Architecture:** Keep `Login` as the authentication state coordinator, extract service-health and password-field responsibilities into focused components, and make `frontend/src/styles/login.css` the single stylesheet for the authentication surface. Add an executable Playwright contract that exercises the real rendered page, using route control only for deterministic health-state UI tests and never for product bug evidence.

**Tech Stack:** React 19, TypeScript, React Router, Vite 8, CSS, Playwright 1.61.

## Global Constraints

- QualiBug frontend remains port 5174 and backend remains port 8088 through the existing Vite `/api` proxy.
- Never present configured-but-unverified integrations as online; the login badge reports only verified API health.
- Preserve the existing backend authentication contracts and the eight-character registration/reset password floor.
- Keep all copy industry-neutral and free of benchmark or customer-specific rules.
- Do not swallow health or authentication failures; unavailable state and diagnostics remain observable.
- Do not retry registration or password reset after a write may have been accepted.
- Do not use subagents; execute in the current session as explicitly requested by the user.

```js
await assertUniqueLabel(page, '账号');
```

### Task 2: Implement truthful health and accessible password units

**Files:**
- Create: `frontend/src/components/auth/ServiceHealthBadge.tsx`
- Create: `frontend/src/components/auth/PasswordField.tsx`
- Modify: `frontend/src/pages/Login.tsx`

**Interfaces:**
- `ServiceHealthBadge(): JSX.Element` calls `getHealth()` and renders `checking | available | unavailable` with `role="status"`.
- `PasswordField(props)` consumes `id`, `name`, `label`, `value`, `onChange`, `onFocus`, `onBlur`, `placeholder`, `autoComplete`, optional `invalid`, optional `describedBy`, and optional adjacent action.
- `PasswordField` produces one labelled input and one `显示密码 | 隐藏密码` toggle without changing the input value.

- [ ] **Step 1: Implement `ServiceHealthBadge` minimally**

Use a three-state union. Treat health as available only when both of these exact facts hold:

```ts
payload.status === 'healthy'
payload.components?.api?.status === 'healthy'
```

For every rejected or malformed response, set unavailable and call:

```ts
console.error('[login.health] Login service health check failed', { error });
```

- [ ] **Step 2: Implement `PasswordField` minimally**

Use a local `visible` boolean, render `type={visible ? 'text' : 'password'}`, and expose a button with `aria-label={visible ? '隐藏密码' : '显示密码'}`. Use `label htmlFor={id}` and keep the optional forgot-password action outside the label.

- [ ] **Step 3: Refactor the Login page**

Import `getHealth` only through `ServiceHealthBadge`. Replace static `引擎在线`, use the approved value copy, add explicit ids/names to all inputs, and replace all password inputs with `PasswordField`. Update mode copy and actions to:

```ts
login: ['登录工作区', '安全登录']
register: ['创建工作区', '创建并进入工作区']
forgot: ['重置登录密码', '重置密码并登录']
```

Use `role="status"` for success, `role="alert"` with a stable id for errors, and `aria-invalid`/`aria-describedby` on relevant fields. Reset visibility by remounting fields with the mode-keyed panel.


Expected: both exit 0 with no warnings.

- [ ] **Step 5: Run the contract and advance GREEN**

Run `npm run test:login-contract`.

Expected: semantic, copy, and password assertions pass; any remaining failure is limited to unfinished visual/overflow requirements in Task 3.

- [ ] **Step 6: Commit the behavior**
