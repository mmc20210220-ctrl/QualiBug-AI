# Phase49：变形关系与差分行为发现引擎

## 为什么需要这一层

企业系统里的许多高价值缺陷并不是某个接口报错，而是多个**本应等价或存在确定关系的业务观察**给出了矛盾结果。例如：

- `status=paid&type=retail` 返回了 wholesale 订单；
- 两个相邻分页包含同一订单，导致用户翻页重复、后续页面漏数；
- 明确请求金额升序，结果却是 `10, 30, 20, 40`；
- 列表显示订单金额 30，详情却显示 999；
- 业务定义为等价的两种查询方式得到不同记录集合。

传统单接口测试很容易把这些接口全部判为“200 成功”。Phase49 将它们转换为可执行的**变形关系（metamorphic relations）**与**差分 Oracle**：模型从 OpenAPI、PRD、配置和真实返回行中推导关系，再对不同有效查询/视图主动取证并寻找反例。

## 自动推导与验证的关系

1. **筛选组合关系**
   - 单筛选结果必须匹配字段值。
   - 两个有效筛选条件组合后，结果必须同时满足两个条件。
   - 有业务主键时，组合结果必须是两个单筛选集合的交集。

2. **分页分区关系**
   - 同一稳定口径的相邻页不得出现同一业务主键。
   - 翻页时 `total` 不得无故变化。
   - 当企业声明默认排序稳定时，两个小页的并集必须等于同范围大页。

3. **排序关系**
   - `asc` 必须非递减，`desc` 必须非递增。
   - 返回全量时，升序主键序列必须是降序序列的反向。

4. **列表/详情投影关系**
   - 同一业务主键的列表和详情必须在共享稳定字段上保持一致。

5. **显式等价查询关系**
   - 企业可配置别名、默认参数、兼容参数等等价表达，系统验证它们返回同一业务集合。

## 安全边界

- `safe_live` **只执行 GET**；不创建数据、不修改状态、不触发异步任务。
- 请求、业务主键和异常字段证据在落盘前脱敏；只保存必要的哈希、行号、字段名和差异。
- 分页、筛选值、详情样本数与响应体大小均有上限。
- 所有发现默认 `needs_human_review`；重复观测会提升置信度，但不会自动写成“确认缺陷”。

## 配置

见：`examples/metamorphic_differential_reasoning_config.example.json`。

最小配置只需给集合接口提供业务主键；OpenAPI 中带有 enum 的筛选参数会自动转为候选关系。对于复杂业务，建议显式补充：

- `filters`：参数与返回字段的映射和值域。
- `pagination`：页码/大小参数和是否要求稳定排序。
- `sort`：排序字段、方向参数和值。
- `detail_path_template`：详情接口与主键占位符。
- `equivalent_query_pairs`：企业定义的等价查询表达。
