# QualiBug 前端最终收口 SPEC

状态：执行中  
目标分支：`frontend/finalization-p0-20260810`  
最终合入：`main`

## 1. 背景

QualiBug 前端已经具备完整的产品页面和真实后端接入能力，包括系统接入、企业资料、运行中心、问题清单、证据中心、发布门禁、覆盖矩阵和后台任务。

当前阶段不再扩张页面数量，而是把既有能力收敛为一条无需人工讲解的客户主链：

`登录 -> 选择/创建客户 -> 接入系统 -> 导入资料 -> 运行前检查 -> 一键检测 -> 查看结论 -> 查看证据 -> 发布决策 -> 回归闭环`

本 SPEC 以四个结果为中心：

1. **易用性**：用户始终知道当前状态和下一步。
2. **价值表达**：首屏先给业务结论，再给技术细节。
3. **分发能力**：报告、证据和协作成为产品传播入口。
4. **可信交付**：不出现错误跳转、乱码、虚假动作、可预测凭据和模糊状态。

## 2. 产品原则

### 2.1 单一主链

普通用户的核心任务只有：接入、检测、处理结果。技术诊断、Scope、Source、Fixture、Connector、运行模板和后台任务属于高级能力，不应抢占首次体验主路径。

### 2.2 结果优先

Dashboard 第一屏必须优先回答：

- 本轮有没有已确认问题；
- 是否存在 P0 阻断；
- 影响哪些业务模块；
- 是否建议发布；
- 下一步应该做什么。

发现漏斗、主链契约、内部技术诊断和证据治理细节放在第二屏或可折叠详情中。

### 2.3 真实状态

以下状态必须严格区分：

- 尚未执行；
- 正在准备；
- 正在检测；
- 部分覆盖；
- 执行被阻断；
- 执行异常；
- 未发现已确认问题；
- 已发现并形成客户可交付证据。

“空结果”不得被展示为“没有问题”。

### 2.4 动作必须真实

按钮名称必须与真实行为一致。不存在直接导出能力时，不得使用“导出报告”作为普通页面跳转按钮。

### 2.5 默认安全

- 不生成可预测默认密码；
- 分享结果默认脱敏；
- 生产环境不暴露测试凭据；
- 外部报告不包含原始密钥、Cookie、Token 和数据库凭据；
- 测试环境和只读熔断状态必须明确展示。

## 3. 目标信息架构

### 3.1 普通用户一级入口

1. 价值总览
2. 开始检测
3. 问题与证据
4. 发布与回归
5. 项目设置

现有路由保持兼容，不要求本轮大规模改路由。覆盖矩阵、后台任务、Connector 明细、技术诊断等继续存在，但降低视觉优先级。

### 3.2 首次接入四步

1. 接入被测系统：服务地址、测试账号、可选数据库。
2. 导入企业资料：PRD、接口规范、数据库结构、历史缺陷等。
3. 运行前检查：自动检查系统、凭据、资料、Fixture 和安全条件。
4. 一键真实检测：真实执行并如实展示执行、阻断、递延和异常。

### 3.3 结果闭环

1. 查看已确认问题；
2. 查看完整证据与回放；
3. 形成发布建议；
4. 分派整改；
5. 发起 Release 回归；
6. 回归通过后关闭。

## 4. 本轮 P0 实施范围

本轮只处理可以在现有架构内完成、且会直接影响首次交付可信度的问题。

### P0-1 首次接入导航一致性

- “导入企业资料”必须进入 `/materials`；
- Dashboard 企业理解区域的资料入口必须进入 `/materials`；
- 保持项目参数不丢失；
- 不新增第二套接入状态。

### P0-2 中文文案完整性

- 修复 Materials 快速连接 URL 校验中的乱码；
- 增加源码契约，禁止已知乱码片段重新进入前端；
- 用户错误信息使用可执行表达，不暴露内部异常堆栈。

### P0-3 动作真实性

- 发布门禁底部按钮若仅返回 Dashboard，文案必须明确为“返回价值总览”；
- 后续真实报告导出由统一导出服务承载，不在本轮伪造未完成能力。

### P0-4 工作区默认凭据安全

- 移除 `${tenantId}123` 形式的确定性密码；
- 使用浏览器安全随机数生成临时密码；
- 保持创建后自动登录流程不回退；
- 临时密码不得写入日志、URL 或本地持久化存储。

### P0-5 技术口径收口

- 前端 README 与实际 Vite + React 19 + React Router 架构一致；
- 删除 Next.js/RSC、`/_next` 等失效说明；
- 明确本地开发端口 5174、后端 8088 和 `/api` 代理口径；
- 以 `npm run ci:gate` 作为统一前端门禁。

### P0-6 自动回归门禁

新增 `test:frontend-finalization`，至少检查：

- 资料步骤路由指向 `/materials`；
- Dashboard 资料入口指向 `/materials`；
- Materials 不含已知乱码；
- ReleaseGate 不存在“导出报告”假动作；
- Settings 不存在可预测默认密码；
- README 不再声明 Next.js/RSC；
- 新契约纳入 `ci:gate`。

## 5. P1 后续范围

P1 不阻塞本轮 P0 合入，但必须作为下一阶段产品任务保留。

### P1-1 接入向导

- 将系统地址、账号、资料和数据库收敛为逐步向导；
- 自动保存草稿；
- 每一步显示完成条件和阻断原因；
- 高级配置默认折叠。

### P1-2 运行过程可视化

展示真实阶段而不是单一 Spinner：

- 企业资料理解；
- 场景与义务生成；
- 测试数据准备；
- 真实探针执行；
- 结果观察与证据收集；
- 交付门禁和报告生成。

### P1-3 角色化价值视图

- 管理视图：风险、发布建议、受影响业务和整改进度；
- 技术视图：接口、请求响应、状态变化、回放和清理回执；
- 测试视图：覆盖、阻断、Fixture、Observer、Evidence 和回归套件。

### P1-4 Finding 协作闭环

增加负责人、处理状态、修复版本、研发反馈、风险接受、误报反馈、外部任务链接和回归状态。

### P1-5 证据和报告分发

- 脱敏只读分享链接；
- PDF/HTML 报告；
- 单问题证据包；
- 飞书、企业微信、钉钉、Jira、GitHub/GitLab Issue；
- 外部报告中的试用和联系入口。

## 6. P2 规模分发范围

- 多项目质量趋势；
- 组织级风险和 ROI；
- 周报和持续质量摘要；
- 合作伙伴客户视图；
- 白标或联合品牌报告；
- 邀请漏斗、分享漏斗和报告转化漏斗。

## 7. 非目标

本轮不做：

- 重写前端框架；
- 大规模修改后端 API；
- 删除现有高级页面；
- 引入第二套业务状态；
- 用静态假数据替代真实后端；
- 为了视觉效果增加新的重型动画；
- 将内部运行状态伪装为客户结论。
