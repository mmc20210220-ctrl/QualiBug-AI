# V2：真实 LLM + Schema 校验 + 本地兜底

V1 是本地规则引擎，用来证明 AI TestOps 闭环。V2 开始接入真实大模型，但企业落地时不能让模型直接写最终脚本。

## 核心原则

```text
PRD / 需求文本
  ↓
LLM 生成结构化资产
  ↓
Schema 校验
  ↓
测试 DSL
  ↓
模板引擎生成 Pytest
  ↓
执行测试
  ↓
失败日志进入 LLM / 本地规则归因
```

## 为什么不是让 AI 直接写代码

直接让 AI 写脚本会带来这些问题：

- 生成代码风格不稳定
- 选择器、数据、断言不可控
- 无法审计每次变更
- 很难做质量门禁
- 出错后不知道是需求问题、模型问题还是脚本问题

V2 的做法是：AI 只生成结构化测试资产，代码由模板引擎生成。这样企业可以管住测试资产的质量。

## V2 新增能力

1. `.env` 配置大模型接口
2. 支持 OpenAI-compatible Chat Completions 接口
3. `--engine auto|local|llm`
4. LLM 输出 JSON 后必须通过 Schema 校验
5. LLM 不可用或输出不合规时，`auto` 模式自动回退本地规则引擎
6. 生成审计日志：`outputs/login/ai_audit_logs/`
7. 失败归因也支持 `auto|local|llm`

## 企业价值

- QA 不再一条条手写用例初稿
- 测试数据不写死，变成数据 profile
- 测试脚本不由模型直接生成，而由 DSL 模板稳定生成
- AI 输出可校验、可审计、可回滚
- 失败归因能自动生成缺陷报告草稿
