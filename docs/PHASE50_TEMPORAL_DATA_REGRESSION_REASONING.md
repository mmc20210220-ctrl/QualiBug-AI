# Phase50：时间维度数据完整性与回归发现引擎

## 为什么这一层重要

真实企业事故经常发生在“接口仍然返回 200”之后：一次发布、迁移、缓存重建或字段映射改动让旧字段批量变空、金额单位从分变元、外部单号被覆盖、关键历史记录消失，单接口冒烟测试通常不会报错。

Phase50 把第一次经过确认的只读观测作为**可信基线**，后续从同一稳定查询再次取证，并只在可证伪的情况下报告数据语义回归。

它不是把最新数据自动当成正确答案：基线默认粘性保存。已经确认的迁移需要显式重置基线，避免一次错误发布把错误数据“学习”为新标准。

## 自动发现的高价值问题

- **关键字段批量缺失**：基线中稳定存在的 legacy 编码、币种、关联字段在新版本中突然大面积为空或消失。
- **字段类型漂移**：数值变字符串、对象变文本等序列化/兼容性回归。
- **不可变属性被批量改写**：同一订单/客户/SKU 的来源系统、外部单号、币种、历史编码等被覆盖。
- **数值单位或精度整体错位**：金额、税额、数量的中位数在样本覆盖相近时整体接近 10、100、1000 倍或其倒数。
- **业务主键新增重复**：过去唯一的订单号、客户编号、SKU 在后续版本开始重复。
- **关键历史记录消失**：企业标注为稳定可见的 canary 历史记录在相同查询口径中不再存在。
- **枚举词表破坏**：当前返回状态不再属于 OpenAPI / 企业配置允许的值域。

## 可信度和误报控制

1. 默认仅比较同一个集合接口、同一 `sample_query`、相近的样本记录数量。
2. 不会把普通状态变化、更新时间变化当成不可变字段回归；只有配置或语义明确的 `immutable_fields` 才会比较。
3. 数值缩放只在字段被标记/推导为数值业务字段，且当前与基线样本覆盖接近时才触发。
4. 关键记录消失只针对企业显式声明的 `canary_identities`，不会用自然增长/自然归档的业务数据制造误报。
5. 每个异常默认 `needs_human_review`；同一指纹跨运行复现后才提升置信度。

## 隐私和安全边界

- `safe_live` **只发送 GET**，不会创建、修改、删除业务数据。
- 基线不保存原始业务行、原始主键或字段值，只保存主键哈希、不可变字段哈希、存在率、类型分布、数值聚合指标。
- 报告证据只保留字段名、哈希、比例和聚合指标；token/header 不落盘。
- 写并发、迁移修复、补数据等动作仍应在隔离沙箱中单独验证。

## 配置

参考 `examples/temporal_data_regression_reasoning_config.example.json`。

关键字段：

- `identity_fields`：跨运行对照的业务唯一键，例如 `order_id`、`customer_code`、`sku`。
- `required_fields`：基线中不得批量消失的字段。
- `immutable_fields`：同一业务主键上不能被批量改写的属性。
- `numeric_fields`：需要检查单位/精度整体错位的金额、数量字段。
- `enum_fields`：企业明确允许的状态/类型值域。
- `canary_identities`：必须持续可见的历史记录，不保存其明文到基线。
- `sample_query`：固定稳定查询口径；应避免“今天新增数据”“最近一分钟”这类高度变化窗口。

## 运行方式

首次运行建立基线：

```bash
python -m ai_test_asset_center.temporal_data_regression_reasoning --project your_project --mode safe_live
```

后续运行会对比基线并输出反例。完成经批准的数据迁移后，显式重建基线：

```bash
python -m ai_test_asset_center.temporal_data_regression_reasoning --project your_project --mode safe_live --reset-baseline
```
