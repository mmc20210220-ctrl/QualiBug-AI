# QualiBug 产品极简原则

## 最高产品门禁

QualiBug 的所有产品、交互、API、运维和交付设计都必须同时满足：

- **操作极简**
- **理解成本最低**
- **傻瓜式操作**
- **接近零维护**

这不是视觉风格建议，而是功能能否进入产品主线的强制门禁。

## 普通用户主路径

普通用户只应理解业务动作：

```text
选择客户
→ 接入系统与企业资料
→ 开始验证
→ 查看真实问题与证据
```

任何新增能力若使主路径增加不必要步骤，必须重新设计。

## 强制规则

### 1. 系统能判断的，不让用户配置

以下内容由系统自动决定，不得进入普通用户路径：

- 解析器、资料格式和来源类型
- 全量或增量同步
- 分页、递归发现与重试
- 去重、版本、检查点和恢复
- 安全删除策略与失败保留
- 限流退避、超时和批次参数
- 内部 ID、哈希、Cursor、Epoch、CAS、Occurrence

### 2. 一次动作完成一个用户目标

配置连接时应合并：

```text
保存
→ 验证连接
→ 首次同步
```

用户只看到一个主动作，例如“保存并开始同步”。

### 3. 工程术语不得进入普通用户路径

前台不得直接显示：

- Connector Instance
- Source Occurrence
- Sync Epoch
- Cursor / Checkpoint
- CAS
- Snapshot Fingerprint
- Retire Missing
- Parser / Adapter 内部名称

这些概念可以保留在代码、审计、诊断包和高级运维界面中。

### 4. 默认安全且无需理解

普通用户不选择删除策略、降级策略、同步模式和重试参数。系统必须使用安全默认值：

- 失败保留上一份可用资料
- 不因远端空结果自动删除
- 不默认降低资料解析质量
- 不返回密钥、正文或原始同步游标
- 服务重启后自动恢复可信状态

### 5. 错误必须可行动

错误信息必须说明三件事：

1. 发生了什么
2. 原有资料是否受影响
3. 用户下一步只需要做什么

禁止把内部异常文本直接展示给普通用户。

### 6. 高级能力藏在简单后面

高级授权、指定节点、多空间范围和运维参数只能放在折叠的高级区域。默认页面只展示完成目标所需的最少字段。

### 7. 维护责任默认属于系统

系统应自动承担：

- 同步状态恢复
- 短暂故障重试
- 限流等待
- 资料版本维护
- 失效授权识别
- 资料新鲜度提示
- 原有快照保护

只有系统无法安全判断时，才请求用户做一个明确决定。

## 设计评审问题

任何功能合入前必须回答：

1. 用户为了完成目标最少需要点击几次？
2. 是否要求用户理解内部工程概念？
3. 是否存在系统本可自动判断却要求用户配置的字段？
4. 失败后用户是否知道唯一下一步？
5. 服务重启、权限变化和远端异常是否需要人工维护？
6. 能否把高级能力折叠，而不影响默认路径？
7. 删除这个字段或按钮后，用户目标是否仍能完成？

只要其中一项不满足，功能不得视为产品完成。
