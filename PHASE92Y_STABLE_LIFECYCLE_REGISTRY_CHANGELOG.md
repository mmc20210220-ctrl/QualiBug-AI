# Phase92Y — Stable Finding Lifecycle Registry

## Goal

Phase92Y fixes a lifecycle blind spot introduced by fix-verification reruns: candidate IDs are generated by the probe compiler and can change after plan refactors.  A finding should not be falsely marked as closed simply because `candidate_id` changed while the same runtime violation still exists.

## Added

- `ai_test_asset_center/runtime_finding_lifecycle_registry.py`
  - Normalizes endpoint paths by replacing path parameters, UUIDs, numeric ids and QualiBug auto ids with `{id}`.
  - Generates durable aliases for each finding:
    - `candidate:<id>`
    - `endpoint:<risk>|<method>|<normalized_path>`
    - `invariant_endpoint:<risk>|<method>|<normalized_path>|<violated_invariants>`
    - `source:<risk>|<method>|<source_ref_fingerprint>`
    - `source_invariant:<risk>|<source_ref_fingerprint>|<violated_invariants>`
    - `title:<risk>|<title_hash>`
  - Applies stable matching between previous and current reports.
  - Migrates current finding lifecycle status to `still_open_after_rerun` when candidate ids changed but stable aliases match.
  - Recomputes `closed_by_rerun` using stable aliases instead of candidate id only.

- `grounded_probe_executor.py`
  - Upgraded engine to `grounded_probe_executor_v14_phase92y`.
  - Adds `phase92y_stable_finding_lifecycle_registry` governance flag.
  - Adds `finding_lifecycle_registry` report section.
  - Adds `summary.stable_lifecycle_match_count`.

- `tests/test_phase92y_runtime_finding_lifecycle_registry.py`
  - Verifies path normalization.
  - Verifies alias generation.
  - Verifies that a changed candidate id does not cause a false close when the same endpoint/invariant signature remains present.
