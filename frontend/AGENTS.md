# Frontend stack (source of truth)

This frontend is a **Vite + React SPA** — not Next.js. Stack: Vite 8, React 19, react-router 7. Dev server runs on port **5174** and proxies `/api` → backend `127.0.0.1:8088`.

- Primary customer journey is now `/dashboard` → `/analyze` → `/verify` → `/findings` → `/release`, with `/integration` and `/settings` as system-level supporting surfaces. `/` redirects to `/dashboard` while preserving project/query context.
- `/analyze` is the unified product-understanding workspace. It composes the existing Requirement Intelligence and Test Intelligence surfaces; it must not merge their truth semantics. Requirement readiness still comes only from the authenticated Requirement Intelligence API, while Test Target coverage still comes only from the authenticated Test Intelligence API.
- `/requirements` remains the backward-compatible Requirement Intelligence surface. Its readiness state must come only from the authenticated Requirement Intelligence API; generic scan status must not be presented as requirement readiness.
- `/test-intelligence` remains the backward-compatible Test Intelligence surface. Its coverage comes only from the authenticated Test Intelligence API. `COVERED` means current supported semantic units have evidence-backed Test Obligations; it is not total test completeness or execution coverage. Obligation state must remain `OBLIGATION_ONLY / NOT_MEASURED / NOT_EVALUATED` until the backend owns a real downstream execution contract.
- `/verify` is the unified runtime verification workspace. It may combine existing real Campaign/Pipeline/Finding/Release results with Test Targets, but must never fabricate Agent steps, browser previews, execution surfaces, or runtime grounding. Until a real event stream and runtime binding exist, missing execution details render explicitly as not reported/not grounded and the existing `/campaigns` run center remains the execution authority.
- Requirement Intelligence and Test Intelligence workspaces must not display Bug Discovery run summaries as if they were product truth. The unified Analyze workspace inherits the same boundary.
- Verify with `npm run lint`, `npm run typecheck`, and `npm run build` (includes `brand:check`) after changes.
- Honesty semantics are non-negotiable: never invent metrics on the frontend; missing backend data renders as 「后端暂未提供 / 未上报 / 待评估 / NOT_MEASURED」states, never as healthy-looking defaults.
