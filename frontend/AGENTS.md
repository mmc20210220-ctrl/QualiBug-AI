# Frontend stack (source of truth)

This frontend is a **Vite + React SPA** — not Next.js. Stack: Vite 8, React 19, react-router 7. Dev server runs on port **5174** and proxies `/api` → backend `127.0.0.1:8088`.

- Primary customer journey is **Agent-first**, not module-first: `/dashboard` (New Task) → `/verify` (Live Workspace) → `/findings` (Agent Findings) → `/release` (Agent Decision). `/analyze` is the Knowledge / Understanding surface the Agent consumes. `/integration` and `/settings` remain supporting system surfaces. `/` redirects to `/dashboard` while preserving project/query context.
- `/dashboard` is **New Task / Agent Home**, not a KPI dashboard. Submitting a quality goal creates a real project-scoped backend Agent Task through `/api/v1/projects/{project}/agent-tasks`; the returned `task_id` is carried into the workspace. The goal is persisted task context, not execution authority: it must not alter runtime scope, invent Test Targets, bypass Runtime Grounding, or bypass Preflight.
- `/verify` is the **Live Workspace**. When a `task` query parameter is present it reads the persisted Agent Task and its backend Event Ledger. Task events are observable work events, not hidden chain-of-thought, and the frontend must never synthesize missing Agent events. Existing Understanding / Planning / Acting / Observing / Evaluating / Finding milestones may still project real Intelligence, Campaign, Finding and Release receipts, but those projections must not be relabeled as Task events unless the backend ledger explicitly records them.
- Agent Task cancellation currently cancels only the orchestration record. Until the backend binds an `execution_run_id`, cancelling a Task must not be presented as cancelling an independent Campaign/Scan. `/campaigns` remains the execution authority.
- `/findings` is the Agent-first Findings surface: conclusion and business impact first, evidence inspection second. Only `isCustomerReadyFinding` results can be presented as confirmed problems. The historical management/list surface remains available at `/advanced-findings`; it is not a second truth source.
- `/release` is the Agent-first Decision surface: recommendation → why → next action. It reuses shared `deriveReleasePresentation` and real project-level `release_gate` / regression / pipeline facts. The detailed historical Gate surface remains available at `/release/details`; it is not a second release authority.
- `/analyze` is the unified Knowledge / Understanding workspace. It composes the existing Requirement Intelligence and Test Intelligence surfaces; it must not merge their truth semantics. Requirement readiness still comes only from the authenticated Requirement Intelligence API, while Test Target coverage still comes only from the authenticated Test Intelligence API.
- `/requirements` remains the backward-compatible Requirement Intelligence surface. Its readiness state must come only from the authenticated Requirement Intelligence API; generic scan status must not be presented as requirement readiness.
- `/test-intelligence` remains the backward-compatible Test Intelligence surface. Its coverage comes only from the authenticated Test Intelligence API. `COVERED` means current supported semantic units have evidence-backed Test Obligations; it is not total test completeness or execution coverage. Obligation state must remain `OBLIGATION_ONLY / NOT_MEASURED / NOT_EVALUATED` until the backend owns a real downstream execution contract.
- Requirement Intelligence and Test Intelligence workspaces must not display Bug Discovery run summaries as if they were product truth. The unified Knowledge workspace inherits the same boundary.
- `/advanced-dashboard`, `/advanced-findings`, `/release/details`, `/campaigns`, `/coverage`, `/jobs`, `/evidence`, `/requirements`, and `/test-intelligence` are advanced / compatibility surfaces. Do not re-promote these internal entities into first-level customer navigation unless the Agent-first product model is intentionally changed and this file is updated in the same change.
- Verify with `npm run lint`, `npm run typecheck`, and `npm run build` (includes `brand:check`) after changes.
- Honesty semantics are non-negotiable: never invent metrics or Agent activity on the frontend; missing backend data renders as 「后端暂未提供 / 未上报 / 待评估 / NOT_MEASURED」states, never as healthy-looking defaults.
