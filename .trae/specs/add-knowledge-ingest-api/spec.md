# 资料导入接口补齐 Spec

## Why
当前前端“企业资料”页面已经支持拖拽上传，但后端缺少可用的资料导入 API，导致拖拽后只能收到 404，无法真正把资料进入知识中心。
本次变更目标是在不改动知识中心核心结构化逻辑的前提下，补齐一个可供前端调用的后端导入接口，让企业资料上传链路真正可用且结果表达真实。

## What Changes
- 新增后端资料导入 API，接收前端上传的项目、类型、文件名和文件内容
- 复用现有知识中心 ingest/资产构建链路，把上传内容写入项目知识资产
- 为不存在项目、空文件、不支持内容等失败场景返回明确业务错误
- 前端继续走拖拽上传，但改为调用真实可用的后端接口
- 导入结果返回真实导入状态与基础元数据，不把“接口不存在”或“仅入库”误报为导入成功

## Impact
- Affected specs: 企业资料导入、知识中心接入链路、前端企业资料上传体验
- Affected code: `phase104_command_center_http_api` 路由、知识中心上传编排、`frontend/src/api/client.ts`、`frontend/src/pages/EnterpriseMaterials.tsx`

## ADDED Requirements
### Requirement: 后端提供可用的资料导入接口
系统 SHALL 提供一个前端可直接调用的资料导入接口，用于把企业资料导入指定项目的知识中心。

#### Scenario: 前端拖拽上传成功
- **WHEN** 用户在企业资料页面向一个有效项目拖入文件并发起导入
- **THEN** 后端接收项目 ID、资料类型、文件名和文件内容
- **THEN** 系统复用现有 ingest 链路处理资料
- **THEN** 响应返回成功状态、项目 ID、资料类型、文件名以及可用于前端刷新列表的基础结果

#### Scenario: 项目不存在
- **WHEN** 前端传入的项目 ID 不存在
- **THEN** 接口返回明确的业务错误
- **THEN** 不写入任何资料

#### Scenario: 内容无效
- **WHEN** 前端上传空内容、缺少文件名或不满足最小导入要求
- **THEN** 接口返回可读错误
- **THEN** 前端能够展示明确失败原因

### Requirement: 导入结果表达真实状态
系统 SHALL 区分“接口可达”“资料已接收”“已进入知识中心 ingest”“结构化结果待后续计算”等状态，不得把仅仅收到请求误报为知识资产已完整生成。

#### Scenario: 导入成功但结构化仍需后续刷新
- **WHEN** 接口已成功把资料提交到知识中心链路
- **THEN** 返回值明确说明本次成功的是导入接收/入链路
- **THEN** 前端刷新资料列表时只展示后端真实已有的 source 状态

## MODIFIED Requirements
### Requirement: 企业资料页面拖拽上传
企业资料页面 SHALL 在拖拽上传时调用真实可用的后端导入接口，而不是命中不存在的占位 API。

#### Scenario: 接口不可用时的提示
- **WHEN** 后端导入接口不可用或返回错误
- **THEN** 前端显示业务可读错误提示
- **THEN** 不展示原始 404 JSON 作为最终用户文案
