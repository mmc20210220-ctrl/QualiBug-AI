# Benchmark Mall 产品需求文档

## 1. 项目背景

Benchmark Mall 是一个面向企业内测环境的电商与供应链管理系统，包含用户端商城、运营管理后台、订单、支付、库存、优惠券、退款、报表等模块。

系统目标：

1. 支持用户浏览商品、加入购物车、下单、支付、取消、申请退款；
2. 支持运营人员维护商品、优惠券、订单和库存；
3. 支持财务人员查看支付与退款；
4. 支持审计人员查看报表与操作记录；
5. 系统应保证权限隔离、状态一致性、金额准确性、库存准确性。

## 2. 用户角色

- buyer：普通买家；
- seller：商家运营；
- warehouse：仓库人员；
- finance：财务人员；
- auditor：审计人员；
- admin：系统管理员。

## 3. 核心业务流程

### 3.1 用户下单

1. 用户登录；
2. 浏览在售商品；
3. 加入购物车；
4. 选择优惠券；
5. 提交订单；
6. 系统校验商品状态、库存、优惠券、地址；
7. 锁定库存；
8. 生成待支付订单。

### 3.2 支付

1. 订单必须处于 `PENDING_PAYMENT` 状态；
2. 支付金额必须等于订单应付金额；
3. 同一订单只能成功支付一次；
4. 支付成功后订单状态变为 `PAID`；
5. 支付成功后记录支付流水。

### 3.3 取消订单

1. 未支付订单可以取消；
2. 已支付订单不能直接取消，只能发起退款；
3. 取消订单后必须释放库存；
4. 已取消订单不能支付、发货、确认收货。

### 3.4 退款 / 售后

1. 已支付或已完成订单可以申请退款；
2. 退款金额不能超过实付金额；
3. 同一订单不能重复成功退款；
4. 退款审批应由财务或管理员处理；
5. 退款成功后订单状态变为 `REFUNDED`。

### 3.5 库存

1. 下单时锁定库存；
2. 支付成功后锁定库存转为已消耗；
3. 取消订单释放库存；
4. 不允许库存为负；
5. 并发下单不得超卖。

### 3.6 优惠券

1. 优惠券必须在有效期内；
2. 优惠券状态必须为 ACTIVE；
3. 必须满足最低订单金额；
4. 用户使用次数不能超过限制；
5. 全局使用次数不能超过限制；
6. 类目券只能用于指定类目；
7. 折扣券必须遵守封顶金额。

### 3.7 权限

1. 普通买家只能操作自己的购物车、订单、退款；
2. seller 可以维护自己负责的商品；
3. warehouse 可以调整库存，但不能改商品价格；
4. finance 可以处理支付和退款，但不能删除商品；
5. auditor 只读；
6. admin 拥有所有后台权限。
